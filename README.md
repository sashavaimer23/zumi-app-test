# Zumi — недвижимость Замбии (Flutter + Supabase)

Покупка и аренда домов, квартир, земли и коммерции. Сделано по вашим макетам: главная, поиск, фильтры, сохранённые, подача объявления в 5 шагов. Сверх макетов добавлены карта с районами, страница объявления, чаты, профиль и вход.

## Что умеет

- **Главная:** популярные районы, недавно просмотренные, популярное на Zumi, лента с категориями.
- **Поиск и фильтры:** все пункты из макета. Сделка и тип аренды (надолго или посуточно), тип объекта, район, цена с гистограммой, спальни, санузлы, ремонт, дети и животные, удобства, от собственника или агента, срок аренды, площадь.
- **Карта (OpenStreetMap):** издалека видны районы с количеством объявлений, при приближении — метки с ценой. Продвинутые объявления выделены зелёным.
- **Страница объявления:** галерея, характеристики, карта, кнопки «Show number», WhatsApp и «Message» (чат).
- **Защита номеров:** номер не приходит вместе с объявлением. Его выдаёт сервер по кнопке — только тем, кто вошёл
  и подтвердил свой телефон, не больше 15 номеров в сутки. Каждый показ записывается. Автор может выбрать «Только чат».
- **Реклама:** баннеры на главной (3:1, листаются), полоски в ленте (6:1, не чаще одной на 8 карточек) и блок
  на странице объявления (2:1). Пометка «Sponsored». Пока место не продано — готовый макет-образец. Размещает рекламу только команда Zumi по договору.
- **Продвижение (агенты):** кампании с датами, паузой и остановкой; показы, клики, звонки и сообщения; отчёт для
  рекламодателя. Команда может выдать продвижение бесплатно.
- **Модерация:** первые 2 объявления нового человека сначала проверяет команда.
- **Коды подтверждения:** WhatsApp, SMS или email. Значок «телефон подтверждён» — только за WhatsApp или SMS.
- **Подача объявления:** 5 шагов по макетам, можно поставить точку на карте.
- **Лимиты:** агент — 5 бесплатных объявлений, собственник — 2. Лимит проверяет сервер, обойти его из приложения нельзя.
- **Продвижение и покупка слотов:** структура в базе готова, в приложении стоят кнопки «coming soon». Платёжный провайдер подключается следующим этапом.
- **Чаты:** сообщения приходят в реальном времени (Supabase Realtime).
- **Демо-режим:** без ключей Supabase приложение работает на встроенных 18 объектах по Лусаке.

## Запуск (первый раз)

Нужен установленный Flutter 3.24 или новее (`flutter doctor`).

```bash
cd zumi
flutter create . --project-name zumi --org com.zumi --platforms android,ios
dart run tool/setup_platforms.dart
flutter pub get
flutter run
```

Первая команда создаёт папки `android/` и `ios/`, код в `lib/` она не трогает. Вторая прописывает разрешения: интернет, галерея, звонки и WhatsApp.

После этого приложение откроется в **демо-режиме**.

## Подключение Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. Включите PostGIS: Database → Extensions → `postgis`.
3. В SQL Editor выполните по очереди:
   - `supabase/001_schema.sql` — таблицы, лимиты, безопасность, районы Лусаки;
   - `supabase/002_features.sql` — поля из фильтров, лента, чаты, защита платных полей;
   - `supabase/003_demo_seed.sql` — 18 демо-объявлений. Этот файл необязательный;
   - `supabase/004_verification.sql` — проверки (Identity, Property, Ownership) и жалобы;
   - `supabase/005_admin.sql` — кабинет команды: роль admin, обращения, отзывы, блокировки, журнал;
   - `supabase/006_profiles_scale.sql` — аватары, страница агента, правка объявлений, превью фото,
     удаление аккаунта, скрытие объявлений без подтверждения 60 дней, индексы.
   - `supabase/007_account_review.sql` — каждый новый аккаунт попадает в кабинет команды («New accounts»),
     причина отказа по лицензии видна пользователю.
   - `supabase/008_campaigns.sql` — продвижение объявлений: кампании агента с датами, паузой/остановкой,
     показами и кликами по дням.
   - `supabase/009_ads_security.sql` — реклама, защита номеров телефонов, модерация первых объявлений,
     коды WhatsApp/SMS/email, блокировка действий для заблокированных, лимиты файлов, бесплатное продвижение.
   - `supabase/010_security_fixes.sql` — WhatsApp агентов только по кнопке (как номер), один подтверждённый номер —
     один аккаунт, проверка продвижения со своей картинкой/ссылкой, показы и клики раз в день с человека,
     красная плашка и кнопка выключения тестовых кодов в кабинете команды.
   - `supabase/011_docs_licence.sql` — удаление фото документов после решения (и через 30 дней без решения),
     пометка «ZIEA licence not verified», продвижение только с проверенной лицензией, правило
     «публиковать только после проверки лицензии» (кнопка в кабинете → Licences).
   - `supabase/012_marketing.sql` — галочка «новости и предложения Zumi» (WhatsApp / почта) при регистрации
     и в Settings; список согласившихся для рассылки: `select * from admin_marketing_list();`
   - `supabase/013_team_help_stats.sql` — роли команды (модератор / владелец, права проверяет сервер),
     раздел «Помощь» со статьями в базе и оценками, обезличенная статистика посещений и поисков,
     панель владельца с выгрузкой в CSV. Первые 14 статей помощи добавляются автоматически.
   - `supabase/014_owner_dev.sql` — аккаунт команды не публикует объявления и не продвигает их; решение по
     кампаниям агентов — у владельца во вкладке «Ads»; отчёт по рекламе по дням; раздел разработчика
     (активные за день и месяц, возвраты, воронки, платформы и версии, ошибки — только числа).
   - `supabase/015_listing_advice.sql` — честный счётчик просмотров (человек — раз в день, свои не считаются),
     просмотры по дням, цены похожих объявлений в районе, советы по объявлению после публикации.
   - `supabase/016_unread.sql` — непрочитанные сообщения: число на значке «Chats» (до 10, дальше «10+»)
     и в списке переписок. Уже запущенному проекту достаточно запустить только этот файл.
4. Скопируйте Project URL и anon key в Settings → API.
5. Запустите приложение с ключами:

```bash
flutter run --dart-define=SUPABASE_URL=https://xxxx.supabase.co --dart-define=SUPABASE_ANON_KEY=eyJ...
```

Для тестов удобно отключить подтверждение почты: Authentication → Sign In / Providers → Email → Confirm email = off.

**Сброс пароля кодом.** Authentication → Email Templates → **Reset Password**: замените текст письма, чтобы в нём был код:

```html
<h2>Reset your Zumi password</h2>
<p>Your code: <strong>{{ .Token }}</strong></p>
<p>If you did not ask to reset the password, ignore this email.</p>
```

**Карта для запуска.** Бесплатные серверы OpenStreetMap годятся только для теста. Зарегистрируйтесь на
[maptiler.com](https://www.maptiler.com) (есть бесплатный тариф), создайте API key и добавьте при запуске
`--dart-define=MAPTILER_KEY=ваш_ключ`.

**Ссылки «Поделиться».** На сайте ссылка берётся из адреса страницы. Для приложений в телефоне укажите адрес сайта:
`--dart-define=SITE_URL=https://ваш-домен`.

**Тариф.** Бесплатный проект Supabase засыпает через неделю без активности и даёт 1 GB под фото.
К запуску переходите на Pro. Чтобы фото занимали меньше места, приложение само делает к каждому фото
маленькую копию для карточек (~800 px).

**SMS-коды** для подтверждения телефона платные: Supabase отправляет их через SMS-провайдера
(Authentication → Providers → Phone). Заложите это в бюджет.

**Удалить демо-объявления**, когда появятся настоящие:

```sql
delete from public.properties where is_demo;
```

## Как устроено

```
lib/
  main.dart                 запуск: Supabase или демо-режим
  config.dart               ключи и адрес тайлов карты
  theme.dart                цвета и шрифты из макетов
  models/models.dart        объявление, район, фильтры, чат
  data/
    repository.dart         общий интерфейс данных
    supabase_repository.dart  работа с сервером
    demo_repository.dart    всё в памяти (демо)
    demo_data.dart          демо-объявления (генерируются tool/gen_demo.py)
  state/app_state.dart      пользователь, избранное, недавно просмотренные
  screens/                  экраны
  widgets/                  карточки, кнопки, фильтры
supabase/                   SQL-миграции
tool/                       скрипты настройки
```

**Лимиты** хранятся в таблице `role_limits` и меняются без обновления приложения:

```sql
update role_limits set free_listings = 10 where role = 'agent';
```

**Выдать доп. слоты вручную**, пока нет оплаты:

```sql
update profiles set extra_listing_slots = extra_listing_slots + 1 where id = '<user id>';
```

**Продвинуть объявление вручную** на 7 дней:

```sql
insert into promotions (property_id, user_id, ends_at, is_free)
select id, owner_id, now() + interval '7 days', true from properties where id = '<listing id>';
```

## Проверки (Verification)

**Плашка Verified** выдаётся человеку, а не объекту, и тогда показывается на всех его объявлениях. Условия:

1. Профиль заполнен (имя как в документе).
2. Телефон подтверждён SMS-кодом.
3. ID-проверка: фото NRC или паспорта и селфи, с галочкой согласия по Data Protection Act 2021.
4. Только для агентов: номер регистрации ZIEA (Estate Agents Act No. 21 of 2000). Команда сверяет его с ZIEA, загружать ничего не нужно.

В профиле есть карточка «Get the Verified badge» с прогрессом «2 of 3». Она ведёт на чек-лист, где кнопка «Continue» всегда открывает следующий шаг. После публикации объявления приложение тоже предлагает пройти проверку, но это не обязательно.

**Дополнительно, для ещё большего доверия (необязательно):**

- **Location Verified**: 3 фото на месте и геолокация не дальше 300 м от точки. Проверяется автоматически.
- **Ownership Verified**: title deed, договор аренды или мандат от владельца. Проверяет команда.

Фильтры: «Only Verified listings» и «Location confirmed on site».

**Закон (кратко, это не юридическая консультация):**

- До запуска зарегистрировать Zumi у Data Protection Commissioner как оператора данных.
- Фото документов удалять после проверки и хранить только результат.
- Документы не должны покидать Замбию без согласия человека. При выборе региона Supabase это важно, юристу стоит это проверить.
- Телефоны пользователей в таблице профилей скрыты от других.

Позже ручную ID-проверку можно автоматизировать через Smile ID: он поддерживает замбийские удостоверения и паспорт и сверяет селфи с фото.

**SMS-коды.** В Supabase откройте Authentication → Providers → Phone и подключите SMS-провайдера (например, Twilio). SMS платные, около $0.05–0.08 за сообщение в Замбию. В демо-режиме код всегда `123456`.

**Одобрить документы** (SQL Editor):

```sql
select * from verification_requests where status = 'pending';  -- заявки
select approve_verification('<id заявки>');                     -- identity / ownership
select approve_licence('<user id>');                             -- лицензия ZIEA сверена
```

Документы и проверочные фото хранятся в приватном хранилище `verification-docs`.

**Жалобы.** «Report this listing» на странице объявления. После трёх жалоб на мошенничество объявление скрывается.

## Кабинет команды Zumi

Кабинет — это скрытый раздел внутри приложения. Его видят только аккаунты с ролью `admin`, доступ проверяет сервер.

**Как стать администратором** (один раз, в SQL Editor):

```sql
update public.profiles set role = 'admin'
 where id = (select id from auth.users where email = 'you@example.com');
```

После этого в профиле появится зелёная кнопка «Zumi team panel», а на компьютере в шапке — ссылка «Team». Первый администратор — **владелец**. Остальных он добавляет сам в разделе **Team & roles**: модератор (клиенты и поддержка: обращения, жалобы, проверки аккаунтов, документов, лицензий и новых объявлений, отзывы, блокировки, статьи помощи) или владелец (всё это плюс реклама, статистика рекламы, общая статистика, раздел разработчика, деньги, настройки, роли и журнал действий). Права проверяет сервер. Аккаунт команды не публикует объявления — свой объект выкладывайте с личного аккаунта.

В демо-режиме: почта со словом `admin` (например `admin@test.com`) — владелец, со словом `moderator` (`moderator@test.com`) — модератор.

**Разделы кабинета:**

- **Inbox** — сколько всего ждёт решения, по разделам. Жалобы на мошенничество показаны первыми.
- **Ads** (владелец) — баннеры (создать, запустить, пауза, стоп) и «Agent campaigns to check» — кампании агентов со своей картинкой, названием или ссылкой.
- **Ad statistics** (владелец) — показы, клики и процент кликов по каждому баннеру и кампании, по дням; отчёт для рекламодателя в CSV.
- **Developer** (владелец) — активные за день и месяц, сколько возвращается, воронки «регистрация → телефон → объявление → контакт», сайт / Android / iPhone и версии, ошибки приложения. Только числа.
- **Statistics** (владелец) — главные цифры за сегодня / 7 / 30 дней: посещения по часам, контакты (показы номера + новые чаты), новые пользователи и объявления, реклама и продвижение, популярные районы и фильтры, жалобы и блокировки. Кнопка «Download table (CSV)» — для отчётов рекламодателям. Всё обезличено.
- **Help articles** — статьи раздела «Помощь»: правка без обновления приложения, вкладка Ratings — «помогло / не помогло» с комментариями, худшие сверху.
- **Team & roles** (владелец) — модераторы и владельцы.
- **ID checks** — фото документа и селфи рядом. Кнопки Approve и Reject с готовыми причинами. После одобрения ссылки на фото удаляются из заявки.
- **New accounts** — все, кто зарегистрировался: телефон, документ, лицензия. «Looks OK», «Block» и
  «Give free promotion» для агентов.
- **Listings to check** — первые объявления новых людей: «Publish» или «Reject» с причиной.
- **Licences** — номер ZIEA агента и кнопка «Open ZIEA» для сверки.
- **Phone views** — кто чаще всех смотрит номера. Кто всегда упирается в лимит 15 в день — скорее всего бот.
- **Ads** — рекламные кампании (черновик, идёт, пауза, закончилась) со статистикой. Добавлять рекламу может только команда.
- **Reports** — жалобы на объявления. Действия: «All OK», «Hide listing» или «Block author» (скрывает все его объявления и запрещает публиковать новые). Объявление можно вернуть.
- **Support** — обращения пользователей в формате чата, с быстрыми ответами-шаблонами.
- **Reviews** — отзывы об агентах и владельцах. Можно скрыть отзыв, вернуть его или ответить публично от имени Zumi. После трёх жалоб пользователей отзыв скрывается автоматически.
- **Activity log** (владелец) — кто, что и когда сделал.

## Перед запуском (чек-лист)

1. Выполнить в новом проекте Supabase один файл `supabase/all_in_one.sql` (это файлы `001`–`015` подряд).
   Затем включить ежедневную уборку документов: Supabase → Edge Functions → Deploy new function →
   имя `purge-verification-docs`, код из `supabase/functions/purge-verification-docs/index.ts`;
   потом Integrations → Cron → New job → каждый день → Supabase Edge Function → `purge-verification-docs`.
   (Кабинет команды тоже удаляет файлы — сразу после решения и при каждом открытии.)
2. Удалить демо-объявления: `delete from public.properties where is_demo;`
3. Подключить отправку кодов (SMS/WhatsApp — например Twilio, email — например Resend) и выключить тестовый режим
   кодов, иначе код 123456 подойдёт любому. Пока режим включён, в кабинете команды висит красная плашка
   с кнопкой «Turn off» (или SQL: `update public.app_settings set value = 'false' where key = 'otp_test_mode';`).
4. Свой отправитель писем (Supabase → Authentication → SMTP) и шаблон письма со сбросом пароля (код `{{ .Token }}`).
5. Ключ карты MapTiler (`MAPTILER_KEY`), адрес сайта (`SITE_URL`) и почта для рекламодателей (`ADS_EMAIL`, по желанию).
6. Юрист проверяет Terms и Privacy (и срок хранения документов без решения — сейчас 30 дней) → в `lib/screens/legal_screen.dart` поставить `kLegalDraft = false`.
7. Supabase Pro (бесплатный проект засыпает) и хостинг Cloudflare Pages со своим доменом.
8. Сделать себя администратором (SQL выше) и проверить кабинет.

## Что дальше

1. **Оплата.** Сервер платёжного провайдера (Mobile Money: MTN, Airtel и карты) вызывает Supabase Edge Function. Функция записывает строку в `payments`, затем в `promotions` или в `profiles.extra_listing_slots`. В базе всё для этого уже есть.
2. **Точные границы районов** для карты (колонка `areas.boundary`) и уточнение координат центров.
3. **Push-уведомления** о новых сообщениях.
4. **Проверка агентов.** Сейчас роль выбирают при регистрации. Поле `is_verified` уже есть, но в приложении пока не используется.
